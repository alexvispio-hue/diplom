# Распознавание страниц

## Реализованный pipeline

В приложении есть два основных сценария:

1. `Фрагмент строки` передает одно изображение локальной TrOCR-модели.
2. `Страница` обрабатывает фотографию листа и запускает один из режимов распознавания полной страницы.

Для страницы используется следующий pipeline:

1. `ImagePreprocessor` читает изображение и пытается найти границы листа.
2. Если лист найден, `DocumentNormalizer` выравнивает его перспективным преобразованием.
3. Изображение переводится в grayscale, очищается bilateral-фильтром и нормализуется CLAHE.
4. Для построчных режимов `PageLineSegmenter` выделяет строки OpenCV-эвристикой.
5. Найденные строки распознаются выбранной моделью и объединяются сверху вниз.
6. В истории сохраняется размеченная копия страницы, список вырезанных строк и координаты найденных строк.

Поддерживаемые режимы страницы:

- `trocr_lines` - сегментация страницы и распознавание каждой строки TrOCR;
- `qwen_lines` - сегментация страницы и распознавание каждой строки Qwen;
- `qwen_page` - передача всей страницы в Qwen без построчной сегментации;
- `qwen_layout` - передача всей страницы в Qwen для получения чернового JSON со строками, текстом и координатами;
- `compare` - параллельный вывод TrOCR и Qwen по каждой найденной строке.
- `hybrid` - распознавание строк TrOCR и Qwen с выбором итогового варианта и пометкой спорных строк для ручной проверки.

В `hybrid`-режиме строки с сильным расхождением TrOCR и Qwen помечаются как требующие проверки. Такая запись автоматически получает статус `partial`, сохраняет `review_notes` и попадает в очередь вкладки `Разметка`.

API-ответ для построчных режимов содержит `line_image_urls` и `line_coordinates`. Координаты возвращаются в формате `line_number, x1, y1, x2, y2` и соответствуют размеченному изображению страницы. Для совместимости с итоговым ТЗ доступны маршруты:

```text
POST /api/recognize/page
POST /api/recognize/page/qwen
POST /api/recognize/page/compare
```

`POST /api/recognize/page` принимает параметры формы:

- `mode` - один из режимов страницы;
- `preprocess` - включить или отключить предобработку;
- `model` - ручной model id для Qwen-эксперимента;
- `max_tokens` - лимит новых токенов для Qwen-генерации;
- `save_intermediate_images` - сохранять ли размеченную страницу и вырезанные строки в истории;
- `return_coordinates` - возвращать ли координаты строк в ответе API.

Если `save_intermediate_images=false`, временные файлы строк используются только во время распознавания и удаляются после сохранения результата. Если `return_coordinates=false`, поле `line_coordinates` возвращается пустым.

В Streamlit эти параметры доступны в блоке `Параметры страницы`. Для Qwen-режимов там же можно задать `Qwen model id` и `Max tokens`; если model id не указан, используется модель из настроек окружения.

Первая версия сегментации реализована в `app/image_processing/page_segmentation.py` с помощью OpenCV. Она предназначена для фотографий или сканов листа с относительно горизонтальными строками. В истории сохраняется размеченная копия страницы, поэтому качество выделения строк можно проверить визуально.

## Следующий нейросетевой этап

Для сложных страниц следует подключить `Kraken` и обучить его baseline-сегментатор. Эта библиотека подходит для задачи, потому что ее сегментатор ищет строки и области текста на странице, поддерживает рукописные документы и может дообучаться на собственных данных.

Для обучения потребуются не вырезанные строки из текущего датасета, а фотографии страниц с разметкой линий текста в формате PAGE XML или ALTO XML. Практический порядок работы:

1. собрать репрезентативные фотографии конспектов;
2. разметить линии текста на страницах;
3. разделить страницы на обучающую и проверочную выборки;
4. дообучить baseline-сегментатор Kraken на GPU;
5. заменить эвристический `PageLineSegmenter` адаптером обученной модели;
6. визуально сравнить выделение строк на фотографиях, которых не было в обучении.

Минимальная команда Kraken для обучения на GPU:

```bash
ketos -d cuda segtrain -f xml training_data/*.xml
```

## Границы текущей версии

Текущий OpenCV-сегментатор и поиск листа не следует считать итоговой нейросетевой моделью. Они нужны как рабочая первая версия приложения и как ориентир для сбора страниц, на которых выделение строк или коррекция перспективы требуют улучшения.

Официальная документация:

- [Kraken: Page Segmentation](https://kraken.re/6.0.0/advanced/segmentation.html)
- [Kraken: Segmentation Training](https://kraken.re/6.0.0/training/segtrain.html)
