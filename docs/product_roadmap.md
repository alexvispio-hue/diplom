# План развития Handwriting OCR до версии 1.0

Статус: рабочий план для версии `0.4.0-dev` после выполнения инженерной части проекта.

Связанное ТЗ: [product_technical_specification.md](product_technical_specification.md).

## 1. Подтверждённое состояние

На 11 июля 2026 года в проекте подтверждено следующее:

- приложение `0.4.0-dev` принимает изображения и PDF, распознаёт фрагменты и страницы, хранит историю, принимает исправления и экспортирует TXT, JSON, DOCX и searchable PDF;
- доступны режимы TrOCR, Qwen по строкам, Qwen по странице, сравнение и гибридный режим;
- подготовлены Windows-скрипты установки и запуска, Docker-конфигурация и release ZIP;
- полный набор тестов содержит 129 проходящих тестов;
- рабочая видеокарта: NVIDIA GeForce RTX 5070 Ti с 16 ГБ VRAM;
- базовая модель `Qwen/Qwen3-VL-2B-Instruct` загружена и проходит локальный inference;
- полный HWR200 подготовлен и валидирован: 3000 документов, 11 010 уникальных страниц, 33 030 вариантов изображений;
- split по авторам не пересекается: 26 634 train, 3264 val и 3132 test примеров;
- 4283 страницы помечены для дополнительной ручной проверки, но структурные проверки датасета пройдены;
- существующий адаптер `qwen-vl-school-hwr200-pages-lora` обучался один короткий цикл, 108 optimizer steps, без validation-метрики и выбора лучшего checkpoint.
- реализованы фоновые jobs, редактор документов, model registry, диагностика, модельные загрузки, gold-review workflow и Windows release packaging;
- текущие Qwen adapters зарегистрированы как `experimental`; production остаётся за проверенной TrOCR-моделью;

Последний пункт принципиален: текущий адаптер является warm start и доказательством работоспособности конвейера, но не готовой производственной моделью.

## 2. Главная цель

Довести проект до локального Windows-приложения `1.0`, которое:

1. стабильно распознаёт русскоязычные рукописные страницы;
2. измеримо превосходит текущий baseline на закрытом тестовом наборе;
3. не теряет сильный режим TrOCR для слов, фрагментов и простых строк;
4. позволяет исправить документ без перехода в сторонний редактор;
5. устанавливается на чистый компьютер и работает без передачи документов во внешние сервисы;
6. воспроизводимо обучает, оценивает и продвигает новые версии моделей.

## 4. Критический путь

### Этап M0. Зафиксировать инженерную базу

Оценка: 1-2 рабочих дня.

Задачи:

1. Провести review и объединить текущий PR для `0.4.0-dev`.
2. Добавить GitHub Actions для unit-тестов, `ruff`, проверки импортов и сборки release-архива.
3. Разделить тесты на быстрые, интеграционные, GPU и dataset tests.
4. Зафиксировать поддерживаемую версию Python и создать воспроизводимый lock/constraints-файл.
5. Изменить статусы Qwen-конвейера:
   - `smoke_passed` означает только проверку конвейера;
   - `training_completed` означает завершение конкретного run;
   - `evaluation_completed` означает наличие отчёта на val/test;
   - `candidate_accepted` означает прохождение quality gate;
   - `production` означает подключение модели как основной.
6. Добавить `run_manifest.json` с commit SHA, dataset hash, base-model revision, parent adapter, seed, аргументами, версиями библиотек, GPU и временем выполнения.

Статус: выполнено в `0.4.0-dev`. Новый клон получает CI-проверки, manifests и разделённые статусы run.

### Этап M1. Создать честный benchmark

Оценка: 2-4 рабочих дня.

Задачи:

1. Зафиксировать текущие split-файлы и их SHA-256.
2. Основную метрику считать по оригинальным страницам. Варианты освещения использовать как отдельный robustness-набор.
3. Сформировать вручную проверенный gold subset минимум из 200 уникальных страниц:
   - не менее 150 страниц HWR200;
   - не менее 50 реальных школьных страниц;
   - разные авторы, освещение, клетка, линейка и чистый лист;
   - отсутствие страниц из train и val.
4. Отдельно проверить случайную выборку из 4283 страниц с флагом review.
5. Получить baseline для:
   - TrOCR по строкам;
   - Qwen3-VL-2B без адаптера;
   - текущего адаптера на 108 steps;
   - текущего гибридного режима.
6. Для каждого варианта сохранить CER, WER, exact-page rate, line recall, latency, peak VRAM и примеры ошибок.

Статус: инфраструктура и 200 gold-кандидатов подготовлены. Осталось ручное подтверждение страниц и baseline-run.

### Этап M2. Довести trainer до производственного состояния

Оценка: 2-4 рабочих дня.

Обязательные изменения:

1. Поддержка отдельных `--train-dataset` и `--eval-dataset`.
2. Evaluation по расписанию, сохранение лучшего checkpoint и early stopping.
3. Полноценный resume из checkpoint, включая optimizer, scheduler, scaler и random state.
4. Фиксированный seed и детерминированный sampler, насколько это позволяет CUDA.
5. Логирование train/eval loss, learning rate, времени шага, VRAM и throughput.
6. Проверка NaN/Inf, OOM и повреждённых изображений с понятным статусом run.
7. Поддержка BF16 как основного режима на RTX 5070 Ti, FP16 как fallback.
8. Group-aware sampler: варианты одной страницы не должны попадать в разные split и не должны чрезмерно доминировать в соседних batch.
9. Отдельный режим обучения только на trusted pages и режим добавления review pages.
10. Автоматический evaluation после завершения обучения.

Статус: trainer и dry-run validation готовы. Настоящий training-run намеренно не запускался.

### Этап M3. Провести обучение Qwen3-VL-2B

Оценка разработки: 1-2 дня. Время GPU определяется benchmark-run.

Последовательность:

1. Запустить 100 optimizer steps и измерить реальную скорость и VRAM.
2. Запустить pilot на 512-1000 trusted страницах.
3. Сравнить два варианта:
   - новый LoRA от базовой Qwen3-VL-2B;
   - продолжение существующего адаптера.
4. Запустить 10% train split и проверить динамику validation CER/WER.
5. Запустить полный train split на одну эпоху.
6. Вторую эпоху запускать только при продолжающемся улучшении validation-метрик.
7. Сравнить разрешения 512 и 768 пикселей по длинной стороне.
8. Сравнить стратегию всех трёх вариантов изображения со сменой одного варианта страницы на эпоху.
9. Сохранить модельную карточку, отчёт и таблицу ошибок.

Предварительная оценка полного run: при 26 634 train примерах, batch size 1 и gradient accumulation 2 получается около 13 317 optimizer steps. Если контрольные 100 steps подтвердят ранее наблюдавшиеся 6-7 секунд на step, одна эпоха займёт около 25 часов; с evaluation и checkpoint следует резервировать 28-36 часов.

Статус: ожидает ручного gold review и отдельного запуска обучения. Команды обучения не запускаются автоматически.

### Этап M4. Подключить лучшую модель к приложению

Оценка: 2-4 рабочих дня.

Задачи:

1. Создать model registry с версиями `experimental`, `candidate`, `production` и возможностью rollback.
2. Показать в UI точную модель, adapter, revision и профиль запуска.
3. Реализовать автоматический router:
   - TrOCR для слова, фрагмента и простых строк;
   - Qwen для полной или сложной страницы;
   - hybrid для спорных строк и проверки результата.
4. Добавить оценку надёжности на основе согласия моделей, качества изображения и OCR-сигналов.
5. Не заменять текст автоматически при низкой надёжности, а отправлять строку в review queue.
6. Добавить regression-набор пользовательских ошибок и прогонять его перед продвижением модели.

Статус: выполнено для registry, checksum, promotion и rollback; Qwen пока не прошёл quality gate и не promoted.

### Этап M5. Сделать полноценный редактор документов

Оценка: 4-7 рабочих дней.

Обязательные функции:

1. Фоновая очередь с pause, cancel, retry и восстановлением после перезапуска.
2. Импорт папки и сортировка страниц по имени и метаданным.
3. Поворот, crop, выравнивание и коррекция перспективы до OCR.
4. Overlay строк и координат поверх страницы.
5. Связь выделенной строки изображения с соответствующим фрагментом текста.
6. Перетаскивание страниц и строк для исправления порядка.
7. Autosave незавершённого документа и журнал изменений.
8. Поиск и замена, пользовательский словарь, отмена и повтор действия.
9. Экспорт в searchable PDF и структурированный JSON; ALTO/HOCR добавить при реальном запросе пользователей.

Статус: основные функции реализованы; осталось подтверждение на чистой установке и пользовательский end-to-end прогон.

### Этап M6. Подготовить установку на чужой компьютер

Оценка: 3-5 рабочих дней плюс тестирование на отдельной машине.

Задачи:

1. Сохранить маленький bootstrap-installer без датасетов и весов.
2. Реализовать профили установки:
   - Lite: TrOCR, CPU или NVIDIA GPU;
   - Full: TrOCR и Qwen3-VL-2B для NVIDIA GPU;
   - Developer: training и evaluation зависимости.
3. Добавить model manager: загрузка, progress, checksum, версия, удаление и восстановление.
4. Хранить пользовательские документы и модели отдельно от каталога приложения.
5. Подготовить Inno Setup или эквивалентный Windows-installer с корректным uninstall.
6. Добавить диагностику CUDA, драйвера, диска, портов и целостности моделей.
7. Проверить чистую установку, обновление и удаление на Windows 10/11.
8. Публиковать release ZIP/installer через GitHub Releases; модели размещать отдельно с model card.
9. Перед публичным выпуском решить вопрос Authenticode-подписи установщика.

Статус: ZIP/Inno Setup, профили, диагностика и инструкции подготовлены; требуется проверка на отдельной Windows-машине.

### Этап M7. Выпустить 1.0

Оценка: 2-3 рабочих дня после закрытия предыдущих этапов.

Условия выпуска:

- все обязательные acceptance criteria из ТЗ выполнены;
- unit/интеграционные тесты и чистая установка проходят;
- model card и dataset manifest опубликованы;
- известные ограничения отображаются в документации и UI;
- есть rollback на предыдущую production-модель;
- release содержит checksum и changelog;
- нет датасетов, секретов, пользовательских документов и training checkpoints внутри установщика.

## 5. Что можно сделать после 1.0

| Идея | Польза | Стоимость | Решение |
| --- | --- | --- | --- |
| Qwen3-VL-4B с QLoRA | Возможный прирост качества сложных страниц | Средняя/высокая | A/B после стабильного 2B |
| Отдельный layout-adapter с JSON | Координаты строк, блоков и заголовков | Средняя | После text-only модели |
| Active learning | Быстрее выбирать полезные страницы для разметки | Средняя | Высокий приоритет после накопления feedback |
| Персональный словарь | Меньше ошибок в фамилиях и предметных терминах | Низкая | Включить в 0.4-0.5 |
| Searchable PDF | Практичный архив документов | Средняя | Включить до 1.0 |
| Локальный поиск по архиву | Поиск текста по распознанным документам | Средняя | После стабильного OCR |
| Исправление орфографии локальной LM | Улучшает читаемость, но может менять исходный текст | Средняя | Только как отключаемый слой с diff |
| Профиль почерка пользователя | Адаптация к одному автору | Высокая | Эксперимент после 1.0 |
| Мобильная съёмка | Удобный захват страниц с телефона | Высокая | Отдельный клиент после 1.0 |
| Tauri/React desktop shell | Более нативный интерфейс | Высокая | Только если Streamlit ограничивает реальные сценарии |

## 6. Что сейчас делать не следует

1. Не назначать Qwen3-VL-8B основной моделью на 16 ГБ VRAM без отдельного quantized benchmark.
2. Не переписывать весь интерфейс до проверки качества и рабочего процесса текущей версии.
3. Не включать все 4283 review pages в основной gold benchmark без ручной проверки.
4. Не выбирать модель только по train loss.
5. Не встраивать многогигабайтные веса в основной Git-репозиторий или bootstrap-installer.
6. Не применять языковую коррекцию скрытно: исходный OCR и исправленный текст должны храниться отдельно.
7. Не считать успешный smoke-run готовностью production-модели.

## 7. Ближайшие действия

Строгий порядок следующей работы:

1. Завершить ручную проверку gold benchmark.
2. Выполнить baseline suite и 100-step performance run.
3. После отдельного подтверждения запустить pilot, 10% run и полный Qwen3-VL-2B.
4. Оценить кандидата по quality gate и regression subset.
5. Проверить чистую установку на втором компьютере.
6. Выпустить `1.0` после прохождения всех quality gates.
