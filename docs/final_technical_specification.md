# Итоговое техническое задание на дальнейшее развитие проекта

> Статус: спецификация этапа перехода от TrOCR к распознаванию страниц. Действующее продуктовое ТЗ до версии 1.0 находится в [product_technical_specification.md](product_technical_specification.md).

## 1. Наименование проекта

Развитие программной системы распознавания русскоязычного рукописного текста на изображениях с использованием методов глубокого обучения и мультимодальных моделей.

## 2. Основание для разработки

В текущей версии проекта реализована система распознавания отдельных рукописных слов и коротких фрагментов текста. Система включает:

- серверную часть на FastAPI;
- пользовательский интерфейс на Streamlit;
- модуль предварительной обработки изображений;
- OCR-модуль на базе TrOCR;
- хранение истории распознавания и пользовательской оценки;
- базовую поддержку распознавания страницы через выделение строк;
- скрипты подготовки данных, оценки и дообучения модели.

Дальнейшее развитие связано с переходом от распознавания отдельных слов к распознаванию полных страниц рукописного текста, а также с добавлением мультимодальной OCR-модели семейства Qwen для более гибкой обработки строк, страниц и сложных случаев.

## 3. Цель проекта

Целью дальнейшего развития является создание расширенной версии системы, способной распознавать русскоязычный рукописный текст на изображениях отдельных строк и полных страниц, сохранять порядок строк, позволять пользователю исправлять результат и накапливать данные для последующего дообучения моделей.

## 4. Основные задачи

Для достижения цели необходимо:

1. Расширить модуль обработки изображений полной страницы.
2. Реализовать или улучшить выделение области листа на фотографии.
3. Реализовать выравнивание изображения и коррекцию перспективы.
4. Развить модуль сегментации страницы на строки рукописного текста.
5. Подключить несколько режимов распознавания: TrOCR, Qwen по строкам, Qwen по странице, гибридный режим.
6. Реализовать сборку распознанных строк в единый текст.
7. Добавить интерфейс выбора режима распознавания.
8. Добавить просмотр найденных строк и результата распознавания.
9. Добавить редактирование итогового текста пользователем.
10. Организовать сохранение проблемных примеров для последующего обучения.
11. Подготовить датасеты строк и страниц для обучения и оценки.
12. Провести эксперименты с Qwen-моделью без обучения и с LoRA/QLoRA-дообучением.
13. Сравнить качество TrOCR и Qwen по метрикам CER, WER, времени обработки и качеству сегментации.

## 5. Общая концепция решения

Система должна поддерживать не один, а несколько вариантов распознавания. Это необходимо, потому что рукописные страницы отличаются по качеству фотографии, освещению, наклону, почерку, наличию клеток, линий, полей и шумов.

Основным вариантом остается построчное распознавание:

1. Пользователь загружает фотографию страницы.
2. Система выполняет предобработку изображения.
3. Система выделяет отдельные строки.
4. Каждая строка передается в OCR-модель.
5. Результаты объединяются сверху вниз.
6. Пользователь проверяет и исправляет итоговый текст.
7. Проблемные примеры сохраняются для будущего дообучения.

Дополнительно должны быть реализованы альтернативные режимы:

- распознавание всей страницы целиком с помощью Qwen;
- распознавание каждой строки с помощью Qwen;
- сравнение результатов TrOCR и Qwen;
- гибридный режим, где TrOCR используется как быстрый OCR, а Qwen как более сильная модель для проверки, сложных строк и полной страницы;
- режим подготовки разметки, где Qwen помогает получить текст и примерные координаты строк.

## 6. Выбор моделей

### 6.1 Базовая модель текущей системы

В качестве существующего baseline используется TrOCR-модель:

```text
kazars24/trocr-base-handwritten-ru
```

Она подходит для распознавания отдельных слов, коротких фрагментов и строк после сегментации. TrOCR следует сохранить в проекте как быстрый и сравнительно легкий вариант распознавания.

### 6.2 Основная Qwen-модель

В качестве основной мультимодальной модели для развития проекта рекомендуется использовать:

```text
Qwen3-VL-8B-Instruct
```

Назначение модели:

- распознавание полной страницы без предварительной сегментации;
- распознавание отдельных строк;
- проверка результата, полученного TrOCR;
- восстановление структуры текста и переносов строк;
- помощь в полуавтоматической разметке строк.

### 6.3 Легкая экспериментальная Qwen-модель

Для локальных тестов и быстрых экспериментов рекомендуется использовать:

```text
Qwen3-VL-2B-Instruct
```

Она нужна для проверки pipeline, промптов, формата данных и интеграции без обязательного запуска тяжелой модели.

### 6.4 Резервный вариант

Если Qwen3-VL окажется слишком тяжелой или нестабильной для текущей среды, допускается использование:

```text
Qwen2.5-VL-7B-Instruct
Qwen2.5-VL-3B-Instruct
```

Эти модели могут применяться как резервный вариант для OCR-экспериментов и сравнения качества.

## 7. Режимы распознавания

### 7.1 Режим TrOCR по строкам

Страница делится на строки, каждая строка распознается TrOCR-моделью. Этот режим является быстрым baseline и нужен для сравнения с Qwen.

### 7.2 Режим Qwen по строкам

Страница делится на строки, каждая строка передается в Qwen с инструкцией распознать только текст на изображении. Этот режим должен лучше работать на длинных строках, пробелах, знаках препинания и нестандартном почерке.

### 7.3 Режим Qwen по полной странице

Вся страница передается в Qwen целиком. Модель должна вернуть весь текст с сохранением порядка строк и переносов. Этот режим нужен как альтернативный baseline и как способ обработки страниц, где классическая сегментация работает плохо.

### 7.4 Гибридный режим

Система получает результаты TrOCR и Qwen, после чего:

- сравнивает распознанные строки;
- помечает строки с сильным расхождением;
- выбирает лучший результат или отправляет строку на ручную проверку;
- сохраняет спорные случаи как обучающие примеры.

### 7.5 Режим помощи в разметке

Qwen используется для подготовки черновой разметки страницы:

- определение строк;
- распознавание текста строк;
- возврат JSON со строками и координатами;
- последующая ручная проверка пользователем.

Этот режим не должен считаться полностью автоматической разметкой. Он используется для ускорения подготовки датасета.

## 8. Архитектура системы

### 8.1 Пользовательский интерфейс

Интерфейс должен поддерживать:

- загрузку изображения слова, строки или страницы;
- выбор режима распознавания;
- включение или отключение предобработки;
- просмотр исходного изображения;
- просмотр изображения с найденными строками;
- просмотр распознанного текста;
- редактирование результата;
- сохранение результата в текстовый файл;
- оценку качества результата пользователем;
- сохранение проблемных примеров.

Рекомендуемые режимы в интерфейсе:

- `Слово / фрагмент`;
- `Страница: TrOCR по строкам`;
- `Страница: Qwen по строкам`;
- `Страница: Qwen целиком`;
- `Сравнение моделей`;
- `Разметка датасета`.

### 8.2 Серверная часть

Серверная часть должна предоставлять API:

```text
POST /recognize
POST /recognize/page
POST /recognize/page/qwen
POST /recognize/page/compare
POST /feedback
GET /history
GET /models
GET /health
```

Метод `POST /recognize/page` должен поддерживать параметры:

- режим распознавания;
- необходимость предобработки;
- выбранная модель;
- максимальное число токенов;
- необходимость сохранения промежуточных изображений;
- необходимость возврата координат строк.

### 8.3 Модуль обработки изображений

Модуль обработки изображений должен выполнять:

- перевод в оттенки серого;
- повышение контраста;
- шумоподавление;
- бинаризацию;
- выравнивание наклона;
- поиск границ листа;
- коррекцию перспективы;
- подготовку изображения к сегментации строк.

Предобработка должна быть отключаемой, потому что на чистых изображениях она может ухудшать результат.

### 8.4 Модуль сегментации строк

Базовый вариант сегментации выполняется с помощью OpenCV:

- бинаризация;
- морфологические операции;
- поиск контуров;
- горизонтальная проекция;
- объединение близких компонентов;
- сортировка строк сверху вниз.

Улучшенный вариант может использовать нейросетевую модель детекции строк:

- YOLO;
- Detectron2;
- специализированная модель детекции текстовых строк.

### 8.5 OCR-модуль

OCR-модуль должен иметь общий интерфейс для разных распознавателей:

- TrOCRRecognizer;
- QwenVLRecognizer;
- EnsembleRecognizer;
- PageRecognizer.

Каждый распознаватель должен возвращать:

- текст;
- имя модели;
- режим распознавания;
- координаты строки или страницы при наличии;
- служебную информацию для отладки;
- время обработки.

### 8.6 Хранение данных

Система должна хранить:

- историю распознавания;
- путь к исходному изображению;
- путь к обработанному изображению;
- найденные строки;
- распознанный текст;
- исправленный пользователем текст;
- оценку пользователя;
- название модели;
- режим распознавания;
- дату и время обработки;
- проблемные примеры.

Рекомендуемая структура:

```text
data/uploads/
data/processed/
data/runtime/
data/training/
data/training/user_feedback/
data/training/page_lines/
data/training/qwen_sft/
data/evaluation/
models/
```

## 9. Данные для обучения

### 9.1 Типы данных

Для развития проекта нужны:

- изображения отдельных слов;
- изображения отдельных строк;
- фотографии полных страниц;
- эталонные тексты строк;
- эталонные тексты страниц;
- координаты строк на странице;
- пользовательские исправления;
- сложные примеры с плохим освещением, тенями, наклоном и разным почерком.

### 9.2 Формат датасета строк

```csv
image_path,text,page_id,line_number,x1,y1,x2,y2
data/lines/page_001_line_001.jpg,пример рукописной строки,page_001,1,120,80,900,145
data/lines/page_001_line_002.jpg,следующая строка текста,page_001,2,118,150,910,215
```

### 9.3 Формат датасета страниц

```csv
image_path,text_path,page_id
data/pages/page_001.jpg,data/pages_text/page_001.txt,page_001
```

### 9.4 Формат датасета для Qwen SFT

Для дообучения Qwen данные должны быть приведены к диалоговому формату.

Пример для строки:

```json
{
  "messages": [
    {
      "role": "user",
      "content": [
        {"type": "image", "image": "data/lines/page_001_line_001.jpg"},
        {"type": "text", "text": "Распознай русский рукописный текст на изображении. Верни только текст."}
      ]
    },
    {
      "role": "assistant",
      "content": "пример рукописной строки"
    }
  ]
}
```

Пример для полной страницы:

```json
{
  "messages": [
    {
      "role": "user",
      "content": [
        {"type": "image", "image": "data/pages/page_001.jpg"},
        {"type": "text", "text": "Распознай весь русский рукописный текст. Сохрани порядок строк и переносы строк."}
      ]
    },
    {
      "role": "assistant",
      "content": "первая строка\nвторая строка\nтретья строка"
    }
  ]
}
```

Пример для разметки:

```json
{
  "messages": [
    {
      "role": "user",
      "content": [
        {"type": "image", "image": "data/pages/page_001.jpg"},
        {"type": "text", "text": "Найди строки рукописного текста и верни JSON с текстом и координатами."}
      ]
    },
    {
      "role": "assistant",
      "content": "[{\"line_number\":1,\"text\":\"пример\",\"box\":[120,80,900,145]}]"
    }
  ]
}
```

## 10. Подход к обучению

### 10.1 Этап без обучения

Сначала необходимо проверить готовые модели без дообучения:

- TrOCR на строках;
- Qwen на строках;
- Qwen на полной странице;
- гибридный режим.

Цель этапа - получить baseline и понять, какие ошибки встречаются чаще всего.

### 10.2 Дообучение TrOCR

TrOCR можно продолжать дообучать на:

- отдельных словах;
- строках;
- пользовательских исправлениях;
- синтетических данных с аугментациями.

Текущий скрипт `scripts/train_trocr_ru.py` следует сохранить и адаптировать под датасет строк.

### 10.3 Дообучение Qwen

Qwen не следует обучать полностью. Для проекта рекомендуется использовать:

- LoRA;
- QLoRA;
- mixed precision;
- 4-bit или 8-bit загрузку модели при нехватке видеопамяти.

Порядок обучения:

1. Подготовить датасет строк.
2. Подготовить датасет страниц.
3. Провести SFT на строках.
4. Провести дополнительный SFT на полных страницах.
5. Добавить пользовательские проблемные примеры.
6. Сравнить модель до и после обучения.

### 10.4 Аугментации

Для повышения устойчивости необходимо использовать:

- изменение яркости;
- изменение контраста;
- шум;
- размытие;
- JPEG-сжатие;
- небольшой поворот;
- перспективные искажения;
- имитацию теней;
- фон тетрадной клетки или линейки.

## 11. Метрики качества

Для OCR необходимо считать:

- CER;
- WER;
- validation loss;
- точность распознавания строк;
- время обработки одной строки;
- время обработки одной страницы;
- долю результатов, оцененных пользователем как правильные.

Для сегментации строк необходимо считать:

- процент найденных строк;
- число пропущенных строк;
- число ошибочно объединенных строк;
- число ошибочно разделенных строк;
- среднее отклонение координат от эталонной разметки при наличии bounding boxes.

Для сравнения моделей необходимо формировать таблицу:

```text
model,mode,dataset,CER,WER,page_time,line_time,notes
```

## 12. Требования к пользовательской обратной связи

Пользователь должен иметь возможность оценить результат:

- `Полностью совпадает`;
- `Частично совпадает`;
- `Не совпадает`.

При оценках `Частично совпадает` и `Не совпадает` система должна сохранять:

- исходное изображение;
- обработанное изображение;
- найденные строки;
- ответ модели;
- исправленный пользователем текст;
- имя модели;
- режим распознавания;
- дату и время;
- метаданные для обучения.

Ошибочный ответ модели нельзя автоматически считать эталоном. Для обучения должен использоваться только исправленный пользователем текст или проверенная разметка.

## 14. Этапы реализации

### Этап 1. Аудит текущего проекта

Проверить существующие модули, очистить рабочую папку от временных данных, зафиксировать текущий baseline TrOCR.

### Этап 2. Базовое распознавание страницы

Доработать загрузку страницы, предобработку, сегментацию строк, визуализацию найденных строк и сборку текста.

### Этап 3. Интеграция Qwen без обучения

Добавить Qwen-распознаватель и проверить режимы:

- строка;
- страница целиком;
- сравнение с TrOCR.

### Этап 4. Подготовка датасета строк и страниц

Сформировать датасет изображений строк, полных страниц, эталонных текстов и координат строк. Разделить данные на train, validation и test.

### Этап 5. Дообучение TrOCR на строках

Адаптировать существующий pipeline обучения под строки и сравнить качество до и после обучения.

### Этап 6. LoRA/QLoRA-дообучение Qwen

Подготовить SFT-датасет, обучить адаптеры Qwen на строках и страницах, сохранить LoRA-адаптеры отдельно от базовой модели.

### Этап 7. Гибридный режим

Реализовать сравнение TrOCR и Qwen, выбор лучшего результата и отправку спорных случаев в очередь проверки.

### Этап 8. Интерфейс проверки и исправления

Добавить удобный просмотр строк, редактирование текста, оценку результата и сохранение исправлений.

### Этап 9. Итоговая оценка

Провести тестирование на реальных фотографиях страниц. Сравнить:

- TrOCR по строкам;
- Qwen по строкам;
- Qwen по полной странице;
- гибридный режим.

## 15. Критерии приемки

Работа считается выполненной, если:

1. В интерфейсе есть режим распознавания полной страницы.
2. Система умеет загружать фотографию страницы.
3. Система выполняет предобработку изображения.
4. Система выделяет строки рукописного текста.
5. Найденные строки отображаются пользователю.
6. Каждая строка может быть передана в TrOCR.
7. Каждая строка может быть передана в Qwen.
8. Полная страница может быть передана в Qwen целиком.
9. Итоговый текст собирается в правильном порядке.
10. Пользователь может исправить результат.
11. Пользователь может оценить качество результата.
12. Проблемные примеры сохраняются для будущего обучения.
13. Подготовлен датасет строк и страниц.
14. Проведено сравнение моделей по CER и WER.
15. Проведено сравнение времени обработки.
16. Получены результаты baseline и результаты после дообучения.
17. Система сохраняет информацию о модели и режиме распознавания.

## 16. Возможные риски

Основные риски:

- нехватка видеопамяти для Qwen3-VL-8B;
- низкое качество распознавания без дообучения;
- нехватка размеченных строк и страниц;
- ошибки сегментации на плохих фотографиях;
- смешивание нескольких строк в одну;
- разбиение одной строки на несколько частей;
- сложность обработки тетрадной клетки и линий;
- большая задержка при распознавании полной страницы через Qwen;
- необходимость ручной проверки данных для обучения.

Способы снижения рисков:

- использовать Qwen3-VL-2B для быстрых тестов;
- оставить TrOCR как быстрый baseline;
- обучать Qwen через LoRA/QLoRA, а не полностью;
- собирать пользовательские исправления;
- хранить тестовую выборку отдельно;
- поддерживать несколько режимов распознавания;
- добавлять нейросетевую детекцию строк только после проверки OpenCV-baseline.

## 17. Ожидаемый результат

В результате развития проекта должна быть получена система, которая распознает не только отдельные слова и короткие фрагменты, но и полные страницы русскоязычного рукописного текста.

Система должна поддерживать несколько режимов распознавания, позволять сравнивать TrOCR и Qwen, сохранять исправления пользователя, формировать обучающие датасеты и постепенно повышать качество OCR на реальных данных.

Главное направление развития - переход от одного OCR-сценария к гибкой архитектуре, где TrOCR используется как быстрый специализированный распознаватель, а Qwen как мультимодальная модель для строк, полных страниц, проверки результата и подготовки разметки.
